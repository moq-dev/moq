--- abstract

This document defines an extension for MoQ Transport {{moqt}} that lets an endpoint declare that advertisements to it must be solicited with SUBSCRIBE_NAMESPACE.
An endpoint that declares nothing continues to receive unsolicited PUBLISH_NAMESPACE, matching unextended peers.
Because sending the option at all identifies a peer that implements this extension, the requirement is enforceable between two supporting endpoints rather than merely advisory.

# Conventions and Definitions
{::boilerplate bcp14-tagged}

An endpoint **advertises** a namespace by sending PUBLISH_NAMESPACE, or NAMESPACE in response to a SUBSCRIBE_NAMESPACE.
An advertisement is **solicited** when carried on a SUBSCRIBE_NAMESPACE stream the receiver opened, and **unsolicited** otherwise.

On a version of {{moqt}} with the NAMESPACE message, the message type alone decides this: PUBLISH_NAMESPACE opens its own request and is always unsolicited, even when the namespace falls under a prefix the receiver subscribed to.
Earlier versions have no NAMESPACE message, so solicited and unsolicited advertisements are indistinguishable there.


# Introduction
{{moqt}} offers two discovery mechanisms (unsolicited PUBLISH_NAMESPACE and solicited SUBSCRIBE_NAMESPACE) without saying on the wire which a peer expects.
Guessing fails in both directions: withholding PUBLISH_NAMESPACE leaves a relay that never asks silent, while sending it unasked floods publish-only peers with every namespace a relay knows.

This extension replaces that out-of-band guess with a SETUP declaration.
It states what an endpoint wants delivered to it, not its role: any endpoint that solicits everything it wants declares it, whether it publishes, subscribes, or relays.


# Setup Negotiation

An endpoint declares whether it requires solicitation with the SOLICIT Setup Option in SETUP ({{moqt}}):

~~~
SOLICIT Setup Option {
  Option Key (vi64) = 0x40B5A,
  Option Value (vi64) = 0 or 1,
}
~~~

A value of 1 means advertisements to the sender MUST be solicited; 0 means unsolicited advertisements are permitted.
A receiver MUST treat any non-zero value as 1.
The two directions are independent.

The option is OPTIONAL, and omitting it asks for the same treatment as 0, except that sending either value identifies the sender as implementing this extension ({{enforcement}}).
An endpoint that implements this extension and does not require solicitation SHOULD therefore send 0 rather than omit the option.


# Requiring Solicitation {#announce}

A peer that implements this extension and receives a declaration of 1 MUST NOT send an unsolicited PUBLISH_NAMESPACE for the remainder of the session; it continues to answer SUBSCRIBE_NAMESPACE with NAMESPACE as usual.
An endpoint MUST process the peer's SETUP before sending its first unsolicited PUBLISH_NAMESPACE.

An endpoint that did not declare 1 can learn a namespace both unsolicited and in answer to its own SUBSCRIBE_NAMESPACE.
Both report the same namespace, so the receiver holds one advertisement until both are withdrawn.


# Enforcement {#enforcement}

On a version of {{moqt}} with the NAMESPACE message, an endpoint that declared 1 and receives an unsolicited PUBLISH_NAMESPACE:

- MUST close the session with a PROTOCOL_VIOLATION if the sender declared SOLICIT (either 0 or 1);
- MUST tolerate the message if the sender omitted SOLICIT.

A receiver MUST NOT treat a PUBLISH_NAMESPACE as solicited merely because its namespace falls under a subscribed prefix.
Versions of {{moqt}} without NAMESPACE are exempt from enforcement.


# Security Considerations

A forged SOLICIT option can suppress advertisements or cause a peer's unsolicited advertisements to trigger a PROTOCOL_VIOLATION, both of which require interfering with SETUP and are already mitigated by the transport security {{moqt}} requires.

SOLICIT carries no authorization semantics: an absent or zero value does not grant permission to learn namespaces, and a peer MUST apply the same authorization checks as without this extension.
The declaration reveals roughly whether an endpoint intends to solicit namespaces; an endpoint that considers this sensitive can omit it.
