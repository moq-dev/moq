--- abstract

This document defines an extension for MoQ Transport {{moqt}} that names the publisher instance behind a namespace.
Peers that negotiate it carry an EPOCH, a UUIDv7 the publisher mints when it starts, on namespace advertisements and on the requests that resolve through them.
A relay can then move a subscription between redundant paths of one instance, and refuse to serve a request from a replacement instance that reused the same names.

# Conventions and Definitions
{::boilerplate bcp14-tagged}

An endpoint **advertises** a namespace by sending PUBLISH_NAMESPACE, or NAMESPACE in response to a SUBSCRIBE_NAMESPACE.

An **instance** is one run of a publisher of a namespace: the content it produces between starting and stopping.
A namespace and an EPOCH name one instance.


# Introduction
{{moqt}} names an object by its namespace, track, group, and object ID, and those names say nothing about which run of a publisher produced it.
A publisher that restarts and counts its groups from zero again reuses names for different content, and a relay holding both runs cannot tell them apart.
A relay with several paths to one namespace also cannot tell whether they serve the same bytes, so it cannot move a subscription between them without risking a gap or a mix of two runs.

This extension carries the instance identity that {{moql}} carries in its Epoch field, without changing any name.
The namespace a subscriber asks for is the same with or without it.


# Setup Negotiation

An endpoint offers this extension with the following Setup Option ({{moqt}} Section 10.3):

~~~
EPOCH Setup Option {
  Option Key (vi64) = 0x40B68
  Option Value (vi64) = 1
}
~~~

A receiver MUST ignore the value.
The extension is negotiated when both endpoints sent the option.
It relies on Setup Options and Key-Value-Pair parameters, so an endpoint MUST NOT send the option, and MUST ignore it, on a version of {{moqt}} earlier than draft-18.

An endpoint MUST NOT send the EPOCH parameter ({{parameter}}) on a session that did not negotiate this extension.
A receiver treats one received on such a session as any unknown parameter, which closes the session.


# EPOCH Parameter {#parameter}

~~~
EPOCH Parameter {
  Type (vi64) = 0x40B69,
  Length (vi64) = 16,
  Epoch (128),
}
~~~

**Epoch**:
A UUIDv7 ({{RFC9562}} Section 5.7) in network byte order.
A receiver MUST close the session with a PROTOCOL_VIOLATION when the value is not exactly 16 bytes, or not a UUID with version 7 and the variant of {{RFC9562}}.

EPOCH may appear in PUBLISH_NAMESPACE, NAMESPACE, PUBLISH, SUBSCRIBE, TRACK_STATUS, and a FETCH that names its track (a Standalone FETCH, or one with a filter).
NAMESPACE carries it in the parameter block defined by {{cluster}}, which a session that negotiated this extension appends to every NAMESPACE; when both extensions are negotiated the one block holds the parameters of both.
A receiver MUST close the session with a PROTOCOL_VIOLATION on an EPOCH in a joining FETCH, which is served by the subscription it joins, or in REQUEST_UPDATE.

Epochs compare as their 16 bytes, which for a UUIDv7 orders them by creation time.


# Identity {#identity}

A publisher mints a new Epoch each time it starts an instance, and MUST NOT serve different content under one namespace and Epoch.
Publishers serving identical content, such as replicas of one encoder, MAY share an Epoch.

Two advertisements of a namespace with the same EPOCH serve the same instance: a receiver MAY move a subscription between them, continuing from the first object the subscriber lacks.
A receiver MUST NOT move a subscription between advertisements with different EPOCHs, or between advertisements without one: it stays on its path and ends with it.
An advertisement without EPOCH names no instance, so nothing says another advertisement serves the same bytes.


# Advertising {#advertising}

A publisher includes the EPOCH of the instance it serves in each advertisement to a peer that negotiated this extension.
A relay forwards the EPOCH it received unchanged, and MUST NOT include one for an advertisement that arrived without one.
A PUBLISH to such a peer carries the EPOCH of the instance whose track it publishes; a relay forwards it as it does an advertisement's, and a PUBLISH without one names no instance.

An advertisement's EPOCH is fixed for as long as it stands, and an update never changes it.
An endpoint replacing one instance with another, both named by an EPOCH, advertises the new instance before it withdraws the old, so the namespace is never absent in between:

- With PUBLISH_NAMESPACE, it sends a new PUBLISH_NAMESPACE with the new EPOCH, and withdraws the old one (PUBLISH_NAMESPACE_DONE, or cancelling it) after the new one is answered. The two travel on different streams, and the answer is what orders them.
- With NAMESPACE, it repeats the live suffix with the new EPOCH, which replaces the old advertisement with no NAMESPACE_DONE between them.

An advertisement that gains or loses an EPOCH names no instance on one side, so the endpoint withdraws it and advertises again.
A receiver MUST close the session with a PROTOCOL_VIOLATION on a NAMESPACE that repeats a live suffix and adds or drops an EPOCH, without a NAMESPACE_DONE between them.

A withdrawal and the advertisement replacing it can travel on different streams and arrive in either order.
A receiver holding several live advertisements of one namespace from a peer treats the one received last as current, so the late withdrawal or update of an older one does not restore the instance it named.

When several instances of a namespace are advertised, a receiver SHOULD resolve new requests to the newest EPOCH, ranking an advertisement without one last, before any other selection rule such as those of {{cluster}}.


# Requests {#requests}

A subscriber includes in SUBSCRIBE, FETCH, and TRACK_STATUS the EPOCH of the advertisement it resolved the request through, when that advertisement carried one.
A request without EPOCH resolves as in {{moqt}}.

A publisher MUST serve a request that carries EPOCH only from that instance.
When the namespace now resolves to another instance, or to an advertisement without EPOCH, it MUST refuse the request with the error it sends for a namespace that does not exist, rather than serve another instance's objects.
A relay forwarding the request upstream includes the EPOCH of the path it chose, which is the same instance.


# Caching {#caching}

A relay keeps the objects of different instances apart.
It MUST NOT answer a request for one instance with an object cached from another, nor with one cached from an advertisement without EPOCH unless the request resolved through that same advertisement.
The same separation applies to a joining FETCH, to subscriptions to an old and a new instance held at once, and to the track aliases and responses of each.


# Peers Without This Extension {#downgrade}

A relay serves a peer that did not negotiate this extension with the names that peer already uses.
It replaces an instance it advertised to such a peer by withdrawing the advertisement before sending a new one, since a second advertisement would read as the same instance; it keeps that peer's established subscriptions on the instance they started on until it ends, and resolves new requests to the current instance.
A relay MAY hide a move between advertisements of the same instance from such a peer.

This is how a relay behaves, not a cache invalidation mechanism.
{{moqt}} identifies an object by its namespace, track, group, and object ID, and a withdrawal does not invalidate that identity.
A relay or client without this extension that keeps objects across a withdrawal can serve one instance's objects for another's names, so a publisher that needs reused names to be safe through such endpoints MUST NOT reuse them.


# Security Considerations

An EPOCH is not authentication.
Any publisher authorized for a namespace can claim any EPOCH, including one another publisher minted, and so splice its objects into subscriptions to that instance.
A relay MUST authorize advertisements and requests by namespace exactly as it would without this extension.

A UUIDv7 reveals when its instance started, to millisecond precision.

# Appendix A: Changelog

## moq-epoch-00
- The EPOCH Setup Option (0x40B68) negotiates the extension on draft-18 and later.
- The EPOCH parameter (0x40B69), a UUIDv7, names the publisher instance on PUBLISH_NAMESPACE, NAMESPACE, PUBLISH, SUBSCRIBE, TRACK_STATUS, and a FETCH that names its track.
- An advertisement's EPOCH is fixed. Another instance named by an EPOCH is advertised before the old one is withdrawn, so the namespace is never absent; one gaining or losing an EPOCH is withdrawn and advertised again.
- A request that carries EPOCH is served only by that instance, and refused as a namespace that does not exist otherwise.
