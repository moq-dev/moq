--- abstract

This document specifies how a MoQ Transport {{moqt}} or moq-lite {{moql}} track carries DEFLATE-compressed payloads.
Each subgroup is one raw DEFLATE stream, sync-flushed at each object boundary, so every object stays self-delimited while compressing against earlier objects in the subgroup and a dropped group never corrupts later groups.
The transport declares compression and each object's inflated size, so a relay forwards compressed bytes to peers that support the extension and inflates them for peers that do not.

# Conventions and Definitions
{::boilerplate bcp14-tagged}


# Introduction
Live metadata and data tracks (catalog snapshots and deltas, telemetry, subtitles) consist of many small, repetitive payloads.
Compressing each payload alone starts a cold window with high overhead; compressing an entire track breaks when groups are dropped, reordered, or joined mid-stream.
Scoping one raw DEFLATE {{RFC1951}} stream to each subgroup captures inter-object redundancy while keeping every group independent.


# Compressed Stream {#stream}
Each subgroup is an independent raw DEFLATE stream {{RFC1951}} (no zlib or gzip wrapper) starting with an empty window; {{moql}} has no subgroups, so each group is one stream.
Datagram tracks are never compressed.

For each object in subgroup order:

- An object with no payload (zero-length) is neither compressed nor decompressed, neither advancing nor resetting the window.
- Otherwise, the publisher compresses the payload into the subgroup's stream and performs a sync flush ({{RFC1951, Section 3.2.4}}, `Z_SYNC_FLUSH`), ending the block and byte-aligning output while retaining the window.
- As in permessage-deflate ({{RFC7692, Section 7.2.1}}), the publisher MUST strip the trailing `0x00 0x00 0xff 0xff` sync-flush marker from the object payload, and the consumer MUST append it before decompressing.
- Each object carries the resulting bytes directly, with no inner length prefix.

The stream is never terminated: a publisher MUST NOT emit a final DEFLATE block, and a consumer MUST treat a final block as malformed and abandon the subgroup.
A consumer decompresses incrementally without treating absent end-of-stream as truncation, and MUST abandon the remainder of a subgroup if any object is missing.
A publisher sends each object's compressed bytes unchanged, so a FETCH starting partway through a subgroup returns objects that decompress only after the subgroup's earlier ones; a consumer not holding those MUST fetch from the subgroup's first object.
The compression level is a publisher choice.


# Declaring Compression {#declare}
Compression is declared at the transport layer, alongside each object's inflated size.
{{moql}} carries a Compression codec id in TRACK_INFO and an Inflated Size on each FRAME from moq-lite-07.
A consumer MUST NOT infer compression from payload bytes, and MUST treat an object whose inflated length differs from its declared inflated size as malformed and abandon the subgroup.

A relay forwards compressed objects unchanged to peers whose transport negotiated compression.
For any other peer, it inflates each subgroup once and forwards the original objects without the compression declarations.
If a declaration is sealed inside Immutable Properties, the relay MUST preserve those bytes and MUST refuse delivery to any peer for which it cannot remove the declaration.
A peer MUST never be sent compressed bytes without the declaration.


# MoQ Transport Signaling {#signaling}
This signaling applies to {{moqt}} draft-18 and later.
An endpoint offers it with the FLATE Setup Option (`0x40B6A`, integer value `1`; any other value is invalid).
Both endpoints MUST offer FLATE before either sends a compressed track.
Setup negotiation is used instead of a Mandatory Track Property so relays can transparently inflate for peers that do not offer FLATE rather than failing the track.

## Compression Track Property {#property}
`COMPRESSION` (property type `0x40B6C`, Track scope) is an integer with value `1` for the format in {{stream}}.
Absence means uncompressed; any other value is invalid.
A receiver MUST refuse a compressed track unless FLATE was negotiated.
The property MAY appear in the mutable list or Immutable Properties, but MUST NOT appear more than once across both.
The declaration applies even when a subscriber suppresses Track Properties in an answer with `INCLUDE_PROPERTIES=0`.

## Inflated Size Object Property {#size}
`INFLATED_SIZE` (property type `0x40B6E`, Object scope) is an integer equal to the payload's uncompressed byte length.
Every Normal Object on a compressed track MUST carry it (including empty payloads, with value `0`); a plain track or status object MUST NOT carry it.
It MAY appear in the mutable list or Immutable Properties, but MUST NOT appear more than once across both.
The object's wire payload length remains the compressed byte length.
The same rules apply to subgroup streams and FETCH streams.

A receiver MUST validate the declared inflated size against the same resource limits as an uncompressed payload before admitting it, and MUST NOT pre-allocate a buffer solely from that declaration.
A relay restates `INFLATED_SIZE` beside forwarded compressed objects and removes a mutable declaration beside inflated objects; a sealed declaration MUST match the inflated length, or the relay MUST refuse forwarding.


# Security Considerations
A shared compression window is a side channel: compressed sizes reveal redundancy across payloads in the subgroup, as in CRIME and BREACH.
A publisher MUST NOT compress secret data and attacker-influenced data in the same subgroup, even when encrypted afterward, since ciphertext lengths remain visible.

To prevent decompression bombs and memory exhaustion, a consumer MUST enforce its payload size limit against the declared inflated size before decompressing, never inflate past that declared size, and SHOULD bound concurrent open subgroup decompression windows (up to 32 KiB each).

# Appendix A: Changelog
{:numbered="false"}

## moq-flate-01
{:numbered="false"}

- Negotiated FLATE signaling adds COMPRESSION and INFLATED_SIZE properties to MoQ Transport draft-18 and later; sealed declarations are forwarded unchanged or refused when incompatible.
- Compression is declared by the transport instead of the application: {{moql}} carries a Compression codec in TRACK_INFO and each object's Inflated Size on FRAME.
- A relay inflates for a peer whose transport does not declare compression.
- Datagram tracks are not compressed and carry no Inflated Size.
- A consumer rejects an object that inflates to other than its declared size, or that ends in a final block.
- A FETCH from partway through a compressed subgroup returns its objects as compressed; a consumer lacking the earlier objects fetches from the first.
