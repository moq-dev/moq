# moq C package

The C API for [rs/moq-ffi](../../rs/moq-ffi), generated by the C backend of `uniffi-bindgen-cpp`, plus `include/moq/moq.h`, which adds the one call the generator cannot: `moq_shutdown`. Nothing here re-implements a function; a shape problem is fixed in moq-ffi, where every binding benefits. User docs: [doc/lib/c](../../doc/lib/c/index.md). Migration guide: [MIGRATE.md](MIGRATE.md).

## Layout

- `CMakeLists.txt` builds moq-ffi as a staticlib with cargo, or consumes an explicit `MOQ_FFI_DIR` native input, renders the C header and its C++ implementation into the build tree, and compiles them as the `moq::c` target. Use it with `add_subdirectory`, or install it for `find_package(moq-c)` and `moq-c.pc`.
- `src/shutdown.c` implements `moq_shutdown`: the moq-ffi runtime workers, then the dispatcher.
- `cmake/` holds the installed CMake package and pkg-config templates. Both locate the prefix relative to themselves and honor `CMAKE_INSTALL_LIBDIR`.
- `build.sh` builds the release archive `release-c.yml` publishes. `--ffi-dir DIR` selects an extracted default-feature native package; otherwise the C++ package's `FFI_VERSION` pin selects one, the same input for both.
- `test/probe.c` exercises the installed package from a C-only project over a real QUIC session, with every callback run on its own loop through `moq_set_dispatcher`.

## Checking

`just c check` builds the package, installs it to a `lib64` prefix, builds the probe against it through `find_package` and, outside Windows, through pkg-config, and runs each. With Ninja available, it also dry-runs a build that adds both `c/moq` and `cpp/moq`, which must share one cargo rule. `just c check --archive FILE` runs the same consumer checks against an extracted release archive. Release dry runs check every archive this way.

The generator is the one the C++ package pins; see [cpp/moq](../../cpp/moq/README.md) to install it without Nix. `flake.nix` lists every place that names its tag.

## Shape

The implementation is C++17 over the generated C++ bindings, compiled into `libmoq.a` (`moq.lib`) beside moq-ffi's staticlib, installed as `libmoq_c_ffi.a` (`moq_c_ffi.lib`) so moq-cpp's copy can share the prefix, so a C program needs no C++ compiler, but its link adds the C++ runtime, which the CMake package and `moq-c.pc` name. Both libraries use the release CRT (`/MD`) on MSVC in every configuration, so an MSVC consumer must too (`CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreadedDLL`); its default Debug runtime (`/MDd`) fails to link with LNK2038.

This package and the C++ package, `moq-cpp`, each embed moq-ffi, so one program links one of them, never both, and they install to separate prefixes.
