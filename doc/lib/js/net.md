# @moq/net

[![npm](https://img.shields.io/npm/v/@moq/net)](https://www.npmjs.com/package/@moq/net)
[![API](https://img.shields.io/badge/API-reference-blue)](/lib/js/api/net)

The TypeScript twin of [`moq-net`](/lib/rs/moq-net): connections, origins,
broadcasts, tracks, groups, and frames, negotiating moq-lite or moq-transport
at setup. The model is [moq-lite](/concept/moq-lite). This page is the behavior
the types do not spell out.

```ts
import * as Moq from "@moq/net";

const url = new URL("https://cdn.moq.dev/room");

// The origin is the routing table. The broadcast survives a reconnect.
const origin = new Moq.Origin.Producer();
const connection = await Moq.Connection.connect({
    url,
    // The first token rides SETUP (and `?jwt=` for older versions); others widen the grant.
    // A reloading `new Moq.Connection({ tokens })` also takes a Signal, set to replace them.
    tokens: [token],
    publish: origin.consume(),
    consume: origin,
});

// Hidden until its first track exists, then announced.
const route = origin.route(Moq.Path.from("chat.room"), { hidden: true });
const track = route.broadcast.createTrack("messages", { timescale: Moq.Time.Timescale.MILLI });
// Undefined while a live track already holds the name.
if (!track) throw new Error("track name taken");
const now = Moq.Time.Timestamp.now();
const group = track.appendGroup(now);
group.writeFrame({ payload: new TextEncoder().encode("hello"), timestamp: now });
group.finish();
route.announce();
```

- **The origin holds the routes, not the connection.** `origin.route(path)` creates a route that owns a new broadcast; fill its tracks through `route.broadcast`. Closing a session withdraws its announcements and leaves the routes for the next one. A route is visible at once unless created `{ hidden: true }`, which keeps it invisible, locally and remotely, until `announce()`. `withdraw()` hides it again and `announce()` brings the same stream back. `close()` retracts it and closes its broadcast, as closing the broadcast does.
- **Answer claimed paths with a route.** `origin.claim(prefix)` returns a `Claim` over a prefix, and `claim.requested()` yields each requested path. Answer with `request.route()`, a new exact route under the claim's identity (a fresh one if the claim names its own), so on `moq-lite-07-wip` readers resolved through the claim continue (older wires mint another identity for it, restarting their subscription), or `request.route({ hidden: true })` to fill its broadcast before `announce()` answers the requesters; closing it or its broadcast before then refuses them as unroutable, so `using job = request.route({ hidden: true })` refuses on a throw. Serve a broadcast you already hold with `request.serve(broadcast)`, or refuse with `request.reject(err)`. `await request.unwanted()` resolves once nobody waits on the answer any more (each requester left, or a cheaper route took them), so a handler can skip work no one will read.
- **End content by finishing tracks.** A broadcast has no finished state. When the input ends, `finish()` each track, then `close()` it; closing a track without finishing aborts it. `fail(error)` ends a track in error instead: unlike `abort`, readers still get every group written, then the error. The broadcast stays announced and keeps serving them until you `close()` it. How long to keep it up for late readers is yours to decide.
- **Requests can pin an identity.** `consumer.request(path, { identity })` resolves only through a route announcing that [publisher identity](/concept/moq-lite#publisher-identities). The resolved broadcast's `identity` names the stream it came through, pinned or not. `origin.route(path)` mints a random identity when it is created and keeps it across `withdraw()` and `announce()`. Unless one is named, a claim moves to a fresh identity each time a job holding its current one ends, and a job takes the claim's. Pass `origin.route(path, { identity: { id, epoch } })` only for a publisher that continues its group starts across restarts and raises the epoch each time.
- **Follow restarts.** `origin.follow(path)` follows whichever publisher identity serves the path: its `active` changes to a fresh broadcast on a restart, clears on an end, and resolves again on the next start, so read it reactively and close it when done. Identities are never stitched, so subscribe again to each new broadcast. Another route of the same identity taking over (identities travel only on `moq-lite-07-wip`; older wires mint one per announcement) keeps `active` as is, and each track subscription resumes there from the first group it lacks. A refusal ends it. Pass `{ identity }` to pin one stream, which it waits for again after an end. `request(path)` instead keeps its accepted identity and ends once that identity stops serving; while pending, it fails `Unroutable` once discovery of its path has synced without a route for it. `await request.broadcast()` on the handle `origin.request(path)` returns gives that broadcast or throws why none came, as Rust's `request(path).await` does; the handle itself is not awaitable, and it still owns the broadcast, so close the request when done. To list what is live, iterate `announced(prefix)`. See [identity and recovery](/concept/identity) to choose between following and holding one identity.
- **Discovery follows what you watch.** A `consume` origin asks the relay for announcements only under the prefixes its readers watch with `announced(prefix)`, `request(path)`, or `follow(path)`, stops asking about a prefix 2s after nothing at or beneath it is watched, and asks again on reconnect. Every request and follower watches its path from creation until closed, so it outlives the listing that found it. A relay that refuses an announce request downgrades that session: requests subscribe blind through it, and followers keep waiting for a session that can discover.
- **Price and rank links.** `cost` on `Connection.connect` or `accept` prices the link on moq-lite 06 and newer and on moq-transport (older moq-lite carries no cost), as Rust's `Client::with_cost` and `Server::with_cost` do: it is added to the route cost of everything the peer announces, and declared in SETUP so the peer charges it too. Our price wins over the peer's; an unpriced link costs `1n`, which routes by hop count, and moq-lite 07 refuses `0n`. Rank a link by giving it a `consume` handle from `origin.withPriority(rank)` (an integer from -128 to 127, higher wins, 0 neutral), as Rust's `with_priority`: requests use the highest-priority route before the cheapest, on moq-lite 07 by the lowest priority of any link along its path. See [multiple CDNs](/concept/moq-lite#multiple-cdns).
- **Connections share by URL and versions.** `new Connection({ url })` pools and reconnects with backoff, which the elements use. An ordered `versions` list, spelled like `moq-lite-06` as in Rust, applies to both WebTransport and WebSocket; equivalent lists share, while a different order or an omitted list gets its own pool entry. Supplying your own transport options or origin selects a private loop. Receive estimates are on demand: observe `connection.probe` reactively or subscribe while you need them; `peek()` alone opens no PROBE stream.
- **GOAWAY moves the session.** The connection dials the replacement at once while the old session keeps serving its groups, up to `goaway.handover` (default 10s, or the relay's deadline when that is sooner). New requests keep opening on the old session until the replacement's route outranks it, which is a restart when the identity did not cross: an unpinned announced request follows the replacement, while a blind or identity-pinned request stays on its accepted stream. When `moq-lite-07-wip` is offered the identity crosses, the replacement serves the same stream, and open subscriptions move across without missing a group. An empty GOAWAY redials the same URL. A redirect stays on the same host unless `goaway.redirect` is `"follow"`, which also presents the tokens on the connection's `auth` handle to the new host. A one-shot session from `Connection.connect` never moves on its own; its `draining` settles with the GOAWAY, so you can connect again and close it. Its URI is the peer's to choose and `goaway.redirect` does not apply, so validate it before dialing it or presenting tokens to it.
- **One send estimate per connection.** `Bandwidth.Allocator` divides it by track priority, max-min fair within a tier. An idle track claims nothing, though its reservation still reads the share it would get. Publishers reserve against it so their targets sum to the estimate. A connection samples the estimate from its transport only while a reservation reads it, so receive-only and lingering connections do no stats work, and the first reservation after none reads `undefined` until one fresh snapshot lands. A transport without an estimate reads `undefined`: the WebSocket fallback, WebTransport without `getStats()` (shipping Chromium), and Safari, whose stub `getStats()` (a 0 RTT at setup) the connection treats as absent.
- **One receive estimate per connection.** `connection.viewers` divides it among watched broadcasts, max-min fair by each viewer's ceiling, so several players on one pooled connection don't each select against the whole downlink. Holding a viewer requests PROBE, and the viewers' ceilings, summed, are the PROBE target a relay advertising `Increase` probes the downlink up to. `setTarget(0)` opts out. `watch`, `update`, and `setTarget` throw a `RangeError` when the ceilings or the target would pass `Viewers.MAX_TARGET` (`Number.MAX_SAFE_INTEGER`), the most a PROBE target carries.
- **List a broadcast's tracks.** `for await (const event of broadcast.tracks())` reports each track the broadcast lists (`added`, with its `Track.Info`), one `synced`, then `added` and `removed` as tracks come and go, until the broadcast ends; leaving the loop stops listing. Over a session it needs `moq-lite-07-wip`, and syncs when the peer does, so a track added after `synced` is new at the source (unless a relay on the way lists a `moq-transport` upstream, which it syncs at once). Over `moq-transport` the listing fails. A track served only on request is never listed. See [discovery](/concept/moq-lite#discovery).
- **One track per name.** Concurrent subscriptions share one request and producer. `createTrack` on a name with a request still queued answers it. Groups are addressed by their start: `appendGroup(start)` opens one at a `Time.Timestamp`, in the track's timescale (rounded down), past every group the track holds, and declares the starts between it and the previous append skipped. The broadcast keeps nothing of an ended track, and a name always means the same content, so a track that replaces it keeps its starts moving forward, as its media time does. Starts are `bigint`, so every ID the wire carries fits, past 2^53 included: `track.createGroup(5n)`, `{ start: 10n }`. A frame's position in its group is its `index`, a `number`.
- **Serve history on request.** `track.requests()` opens a handle that serves the groups readers miss: ones their ranges name below the newest group written that the cache no longer holds, or never did. Each run of misses arrives as a `Track.FillGroups` from `await requests.requestedFill()`, shared by every reader missing it. `accept(start)` it into the cache and write the group's frames as first published, `dropGroups(start, end)` what the source lacks (starts are `bigint`), and serve `wanted()` until it is `undefined`: a reader that leaves or narrows stops wanting its groups. `close()` the fill when done; whatever is still wanted is named dropped. A `fetchGroup` of an uncached group asks the handle at once, even for a group not written yet, which a live write then answers; with no handle open it fails with `NotFound`, as in Rust, and a reader's miss is given up. A reader only asks for what it still wants: history, or what its live join's `max` still allows, so a reader at the live edge never asks. A range starting at a `time` no cached group places asks for the group containing it as a fill one key wide from that time, whose `floor` says how far below it that group may start: a handler that knows its groups only by key serves the key as any other, one with an index may `accept` the group below it or `dropGroups` the key when no group starts from the floor through the time, and the reader starts where the answer says, never where the cached groups happen to. A refusal fails the reader with its error until its ranges change. This serves lite FETCH and lite-07 ranged subscriptions from the same track, as Rust's `requests()` does. A moq-transport FETCH is refused, so a moq-transport reader never reaches it.
- **Timing is per track, with no default.** A track that declares a `timescale` carries a `timestamp` on every frame; one without is [untimed](/concept/moq-lite#subscriptions) and each frame carries `Time.Timestamp.unscaled(group.start)`, its group's key, which has no time: `as`, `asMillis`, and `asMicros` throw on it. A scaled timestamp on an untimed track, an unscaled one on a timed track, or another key throws `TimestampMismatch`. Omitting it means untimed, as in Rust. Nothing stamps a frame for you: the publisher passes the timestamp, and the `@moq/json` producers take it beside each value, as `update(value, at)`.
- **Durations and instants are `Clock` types.** Every duration (`maxAge`, a live join's `min` and `max`, timeouts, RTT) is a `Clock.Duration` and every monotonic time a `Clock.Instant`, from [`@moq/clock`](./clock), which `@moq/net` re-exports as `Clock`: `maxAge: Moq.Clock.Duration.secs(30)`. Neither converts to a number implicitly; read one with an explicit unit, such as `asMillis()`. The wire still carries whole milliseconds, rounded up. Frame timestamps stay `Time.Timestamp`, a tick count at the track's timescale.
- **Only a live join goes stale, under its own `max`, as in Rust.** A range starting `{ live: { min, max } }` (a `Track.Live`) joins `min` behind the live edge, or reaches back past every group for a `null` `min`, and a superseded group it reaches stays deliverable for `max`: it counts from the group's successor, by media time and by wall clock, whichever reaches it first. An omitted `max` is zero and `null` sets no subscriber limit. A group several ranges cover takes the largest, and one any other range covers is history, never stale. A fetch has no budget of its own. Passing the old `delay`, `maxAge` or `maxDelay` key throws a `TypeError` naming a live range's `max`. The publisher's own staleness bound is the separate `Track.Info.maxAge`, which caps every reader.
- **Authored tracks default to a zero `maxAge`.** `createTrack` and `accept` take a `Track.InfoInit`: an omitted `maxAge` is zero, so readers get only the live edge; `null` sets no publisher limit, and a `Clock.Duration` is that bound, as `Info::default()` and `with_max_age(None)` do in Rust. A track whose readers reach back for superseded groups (history, a fetch, a range from a time start) sets one explicitly; media takes `@moq/hang`'s 30-second `Container.MAX_AGE`. `maxAge` is how long a superseded group stays fresh, never the newest group, so a track that writes one snapshot stays readable to a late joiner. A received `Track.Info` uses `null` for none (`maxAge`, `timescale`, and `refresh`'s `ratio` and `interval`), so it serves onward unchanged.
- **Readers ask for a fresh group.** A track whose groups each open with a keyframe or snapshot sets `refresh: { ratio, interval }` in its `Track.InfoInit`, as `Refresh` does in Rust. A join at the live edge asks once the newest group outgrows `ratio` times its first frame (any join without one), and `subscriber.refresh()` asks on demand, by the interval alone when one is set. Either waits until the newest group is `interval` old, so the interval caps how often the publisher restates however many readers ask, and requests coalesce through relays. `await subscriber.refresh()` resolves once the request is sent (forwarded upstream, or read by a local publisher), and aborting `{ signal }` before then withdraws it. The publisher watches `track.demand().refresh` and appends a group while it is `true`; `demand().wanted` says whether anyone subscribes.
- **The cache keeps an idle group for 30 seconds.** A track evicts a group nothing has written for 30 seconds, matching the Rust cache's default expiry; a live track's newest group is exempt until a newer one arrives, unless it failed. Neither `Track.Info.maxAge` nor a live join's `max` changes that window: they only decide which cached groups a reader still receives.
- **Subscription defaults.** `Track.Subscription.default()` returns the default subscription, one live join at the latest group with a zero `max`, which skips a superseded group at once; calling `subscribe()` with no options means the same. A subscription given without `ranges` reads from the oldest group as history.
- **A subscription asks for `ranges`.** Each [range](/concept/moq-lite#subscriptions) starts and ends at the group containing a time (a `bigint` in the track's timescale, or a bare start on an untimed track), both ends included, and a reader reads only its own ranges. An omitted end follows the live edge. A start of `{ live: { min, max } }`, each a `Clock.Duration` rounded up to whole milliseconds, is a live join `min` behind the live edge (`{ start: { live: { min: Duration.ZERO } } }` joins at the latest group); moq-lite 07 carries it, retuning only its `max` in place on an update, and an older peer reads it as no start under its widest `max`. An omitted start is the oldest group the publisher holds, as history. A read whose ranges all end finishes once every group in them is handed out, dropped, or skipped, as in Rust. Over a session before `moq-lite-07-wip`, the publisher starts a time at the first group at or after it. Passing the old `groups` key throws a `TypeError` naming `ranges`; `withRange` only narrows reads locally.
- **Hidden paths** stay out of discovery unless the announce request opts in. See [hidden broadcasts](/concept/moq-lite#hidden-broadcasts).
- **Authorization is in band.** On moq-lite 07 (opt in with `versions: ["moq-lite-07-wip", "moq-lite-06"]`, listing every fallback you still want), `auth.grant` watches what the relay lets this side publish and subscribe to, and `auth.add(token)` presents another token without reconnecting, returning its `Auth.Credential` at once; `await credential.answered` waits for the peer's AUTH verdict on moq-lite 07, resolves at once on moq-transport, and rejects with `Unsupported` on older moq-lite. Publishing outside the grant closes the connection with `SessionCode.Unauthorized`, naming the path. On moq-lite, a subscription or track listing the grant stops covering resets with `StreamCode.Unauthorized` and the session stays up. On moq-transport, `auth.add(token)` only keeps the token for the requests that name it: a route created with the `Auth.Credential` it returns (`origin.route(path, { auth })`) carries it on that announcement's `PUBLISH_NAMESPACE`; `route.setAuth(other)` renews the request. A `Connection`'s `auth` handle (a getter on a pooled connection, following its URL) outlives its sessions: a token added there is presented on every reconnect and keeps riding the announcements that name it, with no re-add or re-announce. A one-shot session's `auth` ends with it, unless `Connection.connect` was given a `new Auth.Handle()` as `auth`.
- **A reconnecting `Connection` reports the peer's verdict on its tokens.** `await connection.answered()` waits for the first answer to the tokens last set (the initial ones before any set): each is granted in band, or is the connection credential a dial carried and the peer accepted. A token the set kept, the connection credential included, counts only once the peer refuses it, and nothing is re-checked after the answer. It rejects with the peer's refusal, with `Unsupported` when the session cannot carry a token in band, or with the connection's end, or with the failure that stopped it retrying its URL while no session answered, such as a refused first dial. On a version without AUTH, a close before the peer's SETUP is its refusal. An app that re-signs its credential for each dial ends the connection on a refusal by aborting `connection.auth`, which makes the loop give up with that error.
- **A relay that reads its credential from the URL.** `urlAuth: true` carries the first token in the URL's `auth` query parameter instead of SETUP and `jwt`, for a relay whose own token kind would reject it. The token is replaced for each dial without changing the URL, and `answered()` judges it like any connection credential. A replacement on a live session takes a redial, so `answered()` then waits for it. A URL that already has a `jwt` keeps it, and every token rides AUTH.
- **A graceful close waits.** `await connection.close()` withdraws announcements and drains for up to one second. `moq-lite-05` and newer wait for the subscriber to receive finished tails; older Lite versions wait only for transport ACKs. IETF media streams are not drained. `abort()` ends immediately.

Examples:
[`js/net/examples/`](https://github.com/moq-dev/moq/tree/main/js/net/examples).
Runs in the browser and, over WebSocket, in Node, Bun, and Deno; see
[server-side](/lib/js/#server-side). The WebSocket fallback and the moq-transport stack load
on demand as separate chunks, so a moq-lite session WebTransport wins within its head start
never downloads them.
Grant prefixes and discovery scopes are on the
[concept page](/concept/moq-lite#grants-and-listings).

Groups retain a 32 MiB live tail without limiting their lifetime or frame count.
Readers that fall behind the shed front receive `Evicted`; tracks that
`refresh` also request a fresh group. A join never starts at an arbitrary
frame in the retained tail.

Frames have no size cap either. `group.createFrame({ size })` returns a
`Moq.Frame.Producer` that writes one in pieces, and `group.nextFrame()` returns a
`Moq.Frame.Consumer` that reads it as it arrives with `readChunk()`, so a
file-sized frame passes through holding only the tail. The tail sheds a large
frame's oldest 1 MiB segments while it is written, so a chunk reader more than
the tail behind gets `Evicted`. `readFrame()` still works for any size, but it
collects the frame into one buffer. A compressed track keeps a 32 MiB frame
limit, because its header declares each compressed slice's size before the
bytes:

```ts
const frame = group.createFrame({ size: file.size });
for await (const chunk of file.stream()) frame.write(chunk);
frame.finish();

const reader = await consumer.nextFrame();
for (let chunk = await reader?.readChunk(); chunk; chunk = await reader?.readChunk()) save(chunk);
```
